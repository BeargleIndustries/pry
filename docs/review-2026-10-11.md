# Pry: full review and update ideas (2026-10-11)

Scope: every tracked source file (sidecar, Tauri shell, Svelte UI, scripts, docs). Findings marked **[verified]** were reproduced against the installed runtime (`%LOCALAPPDATA%\Pry\runtime`, GPT-2 small, torch 2.5.1 / TransformerLens 2.15.4 / SAELens 5.11.0). The rest come from reading the code.

Baseline checks:
- `pytest`: 25/25 pass. These only cover schemas. Nothing tests inference.
- `cargo check`: passes, with dead-code warnings.
- `npm run check`: 42 errors, all caused by missing `@types/node` (vite/kit typings). There are also 18 a11y warnings.
- `src-tauri/Cargo.lock` and `ui/package-lock.json` were left out of the 0.1.1 release commit. They are still modified in the working tree.

## 1. Critical: wrong results, or users locked out

### 1.1 GPU users silently get CPU-only torch **[verified on this machine]**
This machine has an RTX 4070 SUPER, and `nvidia-smi` works. The managed runtime still has `torch 2.5.1+cpu` (`torch.version.cuda = None`), so everything runs on CPU. File timestamps show torch being rewritten *after* sae-lens was installed. That points to a later `pip install` step (TL / sae-lens / sidecar package, none of which use the cu124 index) re-resolving torch from PyPI. The bootstrap log is never written to disk, so the exact cause can't be confirmed after the fact.
- `src-tauri/src/bootstrap/pip.rs:27-75`: only step 1 uses `--index-url cu124`. Steps 2–5 have no constraint keeping `torch==2.5.1+cu124`.
- Fix: write a `constraints.txt` (`torch==2.5.1+cu124`) and pass `-c` plus the cu124 `--extra-index-url` to every pip step. After install, run `python -c "import torch; assert torch.cuda.is_available()"` and fail loudly or warn. Persist the bootstrap log to `Pry/logs/`.
- Related: on 2026 hardware, torch 2.5.1/cu124 has no Blackwell (RTX 50xx, sm_120) kernels. Those users would hit "no kernel image" errors. Plan a move to torch ≥2.7 + cu128.
- Related: nothing in the UI tells the user which device is in use. Add a CPU/GPU badge.

### 1.2 CPU-only machines are fully locked out
`presets_compat.rs:66` marks every preset `Insufficient` when there's no GPU (including Intel iGPUs reporting little dedicated VRAM). The onboarding picker disables Insufficient cards, ModelSwitcher only lists Comfortable/Tight, and PresetList hides Switch. Result: a laptop user finishes setup and can't load anything. Run is disabled with "No model loaded". GPT-2 small and Pythia-70M run fine on CPU, and the bootstrapper already installs a CPU wheel for this case. The CPU hardware report even says "Generation will run on CPU and will be slow" (`hardware.rs`), which contradicts the block. For an accessibility-first app, this is the largest group of people being shut out.
- Fix: add a `CpuOk` verdict (or treat small presets as Tight on CPU) with plain-language "slower, but works" copy.

### 1.3 "Mean" attention aggregation is a flat grid **[verified]**
`PanelA.svelte:110` takes the mean of a softmax row, which always equals `1/seq_len`. All 144 heads came out at exactly `0.066667`, so the heatmap is one uniform color. Tutorial step 1.6 *switches to Mean and says "watch the pattern change"*. Entropy is also normalized by `log(seq_len)` including masked future positions. It should use `log(pos+1)`.
- Fix: in FROM mode, replace Mean with something meaningful, such as "distance looked back" or "attention to previous token". Or keep Mean only for TO mode (attention *received*, which does vary). Update the tutorial and tip copy (`tips-registry.ts`, the agg tip, and `driven-steps.ts` step 1.6).

### 1.4 Circuit Map edges are fabricated, and usually absent **[verified]**
`inference.py:1341-1365` gives every edge into node N the same weight, `mean_q(pattern[:, last])`, whatever the source. Under causal masking that's `pattern[last,last]/seq_len`, so edges only appear when a head attends mostly to itself on short prompts. On the IOI prompt: 32 nodes, **0 edges**. Meanwhile the tooltip says "This is the actual circuit the model used" and "closest to what Anthropic's internal tools look like" (`tips-registry.ts:204`). That overclaims, and the Anthropic comparison isn't something we can source.
- Fix options: (a) rename to "Key parts map", drop edges, and soften the copy; (b) compute real edges, e.g. a cheap path-patching or "attention from target head's query to source position × source DLA" heuristic, clearly labeled approximate.
- The "Patching" source button (`CircuitPanel.svelte:116`) always returns HTTP 501. Hide it until it's implemented.

### 1.5 Pythia SAE is fed the wrong layer
`presets.json` says the Pythia SAE is trained on `hook_resid_post`, but `inference.py:217, 425, 753, 966` always hook `hook_resid_pre`. So `resid_pre[3]` (= `resid_post[2]`) gets encoded with a layer-3-post SAE, which means garbage features for Pythia. Fix: use `manifest.sae.hook` everywhere.
- Bonus **[verified]**: SAELens has Pythia-70M SAEs for **all 6 layers** (`blocks.0-5.hook_resid_post`). `presets.py:48` limits it to `[3]`.

### 1.6 Analyses silently run on the wrong prompt or wrong SAE
- `+page.svelte` sends the *current text box* `prompt` to Logit Lens, DLA, Steer, Ablate, Circuit, and SAE layer switch. If you edit the prompt without pressing Run, the panels show results for a different sentence than the token strip. `handleLayerSwitch` merges new-prompt features into old-prompt tokens. Fix: use `response.prompt`.
- Feature ablation picked at layer 8, then an SAE layer switch to 2: the sidecar encodes the layer-8 hook with the *layer-2* SAE (`inference.py:966-979` always uses `loaded.sae`). `run_steer` has the same mismatch if `sae_layer` ≠ the loaded layer (`inference.py:752`). Fix: reject mismatched layers server-side and clear `featureAblations` on layer switch.

## 3. Medium: correctness and robustness

- **The feature "confidence" is really label word count** (`inference.py:130-136`). The UI shows "confidence: high" for any label of 3+ words. It's misleading in a teaching tool. Rename it (e.g. "label quality") or drop it.
- **Attention is truncated at 64 tokens** (`inference.py:234`), but `attention_truncated` is never surfaced: it isn't in `types.ts` and no UI uses it. Focused tokens past 64 show all zeros.
- **DLA ignores the final LayerNorm scale and the embedding/bias terms.** The ranking is mostly right, but the numbers don't add up to the logit. That's fine if the copy doesn't imply they do. DLA also doesn't refresh when the focus token changes.
- **Patching** checks length only on the server. Add a live token counter for both prompts. The default pair ("cat" vs "dog" sat on the) predicts nearly the same thing, so effects are tiny and confusing. Use a canonical IOI pair. The view switches on local `patchType`, not `response.patch_type`.
- **Steering:** `selectedFeatureId` persists across new runs even when that feature is no longer in the list. The diff is by whitespace position, so one inserted word marks everything after it as changed. Generations repeat the prompt.
- **Sparkline** only sees each token's top-5 features, so "0" often means "not in the top 5". The tip mentions this, but the visual implies otherwise.
- **`crash.rs:72`**: `&sanitized[..MAX_LOG_BYTES]` can panic on a UTF-8 boundary. It's called from the panic hook, which turns a panic into an abort. Use `floor_char_boundary` or a char-safe truncation.
- **Request validation:** `feature_id`, `head`, and `layer` aren't range-checked against the actual model, so out-of-range values give a 500 rather than a 400.
- **Load progress is fake.** "Preparing SAE…" fires *after* the SAE has already loaded (`main.py:168-174`). There's no real download progress, and a first GPT-2 download looks frozen at 25%.
- **ExitRequested** spawns an async shutdown that probably never runs before process exit. The job object handles cleanup anyway, so it's only a misleading comment.
- **Sidecar URL caching:** `getBase()` caches forever, and after 30 s it falls back to `:8765` (always wrong under Tauri's random port), which produces confusing errors.
- **Export:** blob `<a download>` + immediate `revokeObjectURL` is unreliable in WebView2. The app already has `dialog:allow-save` and fs write to `$DOWNLOAD` but doesn't use them. The tip promises "or a screenshot… picking up where you left off", and neither exists.
- **Security (low):** the sidecar has no auth and accepts any body regardless of Content-Type, so any web page can fire `text/plain` "simple" POSTs at `127.0.0.1:<port>` (no-cors). Impact is limited to triggering loads/compute, and the random port helps. A per-launch token header would close it.
- **Bundle list:** each `.py` file is listed by hand in `tauri.conf.json` resources. Adding a module silently breaks installed builds. Use a glob.

## 5. Update ideas that fit Pry's goals

Pry's angle is plain language, local, "poke it and see". The ideas below build on that, roughly in order of value per effort.

1. **A real induction-heads demo.** The default prompt is already the repeated cat sentence, and the done page already promises it. Auto-score heads for "previous-token" and "induction" patterns and highlight them in the grid. It's the most famous result in the field, and it looks great.
2. **Plain-language readouts on every panel.** Rule-based, no LLM. For example: "The model is 62% sure the next word is *mat*. It settled on that around layer 9. The biggest single push came from L9.H6." This turns every chart into a sentence a newcomer can repeat.
3. **Experiment cards ("Try this").** A gallery of one-click setups: IOI name-mover, induction, he/she bias, capital cities, counting, plus pre-validated same-length patching pairs. Each comes with "what to look for" and "what researchers found".
4. **Find and steer any concept.** Today you can only steer features that already fired on your prompt. Add Neuronpedia's search-by-description so you can steer "the ocean" into any prompt. That's the most fun demo in interpretability.
5. **Compare mode.** Two prompts side by side showing feature, prediction, and attention diffs (e.g. "he" vs "she" in the doctor sentence). This reuses existing endpoints and makes the bias demo actually comparative.
6. **Lab notebook and shareable report.** Save runs with notes, then export a self-contained HTML report instead of a raw JSON blob. This fixes the export overpromise and supports sharing (the trading card shows sharing already fits the brand).
7. **"Watch it write" generation view.** Token-by-token output with the probability of each chosen token and the runner-up, plus a temperature slider. This explains sampling, which is the most common newcomer question.
8. **Attention "lines" view.** BertViz-style arcs from the focused word back to earlier words. It's more intuitive than the 12×12 grid as a first view, with the grid kept as the expert view.
9. **Engine status chip.** GPU/CPU, model, SAE layer, and a "restart engine" button. This pairs with 1.1, 1.2, and 2.5.
10. **Accessibility pass.** Keyboard navigation for the grids (18 svelte a11y warnings), screen-reader summaries (these could reuse #2), and colorblind-safe palettes for patching and DLA.
11. **Glossary hovers.** Dotted-underline jargon (logit, head, SAE, residual) gets a one-line plain definition. The tips already have the copy.
12. **Unlock Gemma-2-2B** once 2.2 is fixed. Gemma Scope has broad Neuronpedia coverage, so it would be the "graduate" model.
